# @donotdev/components

## Unreleased

### Minor Changes

- Navigation active state in the header row (`header[role='banner']`): links of the current page (single `HeaderNavigation` links, inline `DnDevNavigationMenu` links and triggers) show a `--border-width` underline in `--accent` and a semibold label, with no fill: the UnderlineNav pattern. Everywhere else (sidebar, overflow dropdown, sub-menus, burger panels, portaled out of the header) the active fill (accent 50%) is unchanged. Migration: none.
- `@donotdev/ui` `HeaderNavigation`: `badge` (single-item mode), a count on the item's icon, added to the link's accessible name ("Orders (3)"); `0` or absent shows none.

- Accordion: `itemClassName`, a class added to each item (`.dndev-accordion-item`). Absent: markup unchanged.

- Text: `level="h5"` and `level="h6"` have their own size and weight (h5 `--font-size-sm`, h6 `--font-size-xs`, both semibold). They had no rule: the size came from the element `as` renders (`<Text as="h3" level="h6">` took the h3 reset size, a div inherited its parent's). A Text nested in another Text with no `level` and no `weight` keeps its parent's weight; it was forced to medium, so a coloured `<Text as="span">` in a bold heading rendered thin. `strong` keeps its semibold. Migration: none; remove inline `fontWeight: 'inherit'` workarounds.
- DataTable cell editors `date` and `datetime` (`TableCellEdit.type`, with `timeZone`: the app's IANA zone, required for them) (owner decision 2026-11-25 C1, `docs/decisions/2026-11-25-admin-ui-leftovers.html`). The editor is the `DatePicker` (calendar date `YYYY-MM-DD`; a stored instant edits as its day in `timeZone`) or the `DateTimePicker` (wall time in `timeZone`, stored as the UTC instant, `toISOString()`), opened in place like the other editors; each complete value is stored (one undo step), Enter / Shift+Enter move a row, Esc closes, Ctrl/Cmd+Z undoes, leaving the picker and its calendar closes it. Paste (single value or a spreadsheet block) and bulk edit (the selection bar shows the same picker) parse `YYYY-MM-DD[ HH:MM]`, `DD/MM/YYYY[ HH:MM]` (`/`, `.`, `-`) and ISO instants with `Z` / an offset; a date that does not exist stays as typed and flagged invalid. A `date` / `datetime` editor without `timeZone` throws. The picker in a cell looks like the text, number and select editors (`.dndev-table-cell-date`, Table.css: the cell's height, padding and background, no field border, radius or shadow, the inside focus ring, the invalid outline; its mobile native input too); it had no style and drew a full form field inside the cell.
- Time zone helpers (`utils/date`): `isoToZonedWallTime(iso, timeZone)`, `zonedWallTimeToISO(wall, timeZone)` (a spring-forward gap moves forward, a repeated hour takes the standard-time occurrence), `toZonedCalendarDate(value, timeZone)`, `formatWallTime(parts, locale, options)`. `ComponentLocale.timeZone` (the app's zone, set by `@donotdev/ui` from `getAppTimeZone()`; `UTC` without a provider).
- `DatePicker` / `DateTimePicker`: the screen-reader announcement of the picked value reads the wall time as written (`formatWallTime`, never shifted by the machine's zone). The DateTimePicker value stays a wall time `YYYY-MM-DDTHH:MM`: callers store it with `zonedWallTimeToISO(wall, timeZone)` (crud's date field and the DataTable editor do).

- DataTable reads as an admin grid (owner decisions 2026-11-25, `docs/decisions/2026-11-25-admin-ui.html` P1-P3, P6, P7, P9, P14b, P15). **Look:** header on the background of what the table sits on (page `--background`; in a Card, Dialog, AlertDialog or Sheet, `.dndev-surface`: `--card`, pinned cells too, so no page-coloured band in a dialog) with a 1px bottom border, muted 13px medium labels, sticky at the top of the table's scroll area (the wrapper scrolls both ways, at most the viewport height); no zebra striping (no prop); faint row hover; checked rows tinted with the primary 8% (`data-selected`). The sort arrow shows only on the sorted column (`data-sorted`, `aria-sort`) or on hover of a sortable header (pointer cursor kept), overlaid out of the flow at the header's inline end (inline start in end-aligned columns), covering the end of a label that fills the column: showing it never changes a column width (P4). Cells never wrap: "…" with a native `title` tooltip of the full text, set on hover only when cut; cells up to 24rem unless the column sets `width` (now also its max width). End-aligned cells use tabular digits. **Density:** `--table-row-height` token (40px, the touch target on a coarse pointer; declared on `:where(:root)` in `Table.css`, override it in the app theme), cell padding `0.375rem` inline / 0 block (Excel-like), open-link and checkbox columns one row height wide (were 88 / 57px). 25 rows per page by default (was 12); the loading skeleton has as many rows as the page (3 without pagination). **Editable cells** show `render` of their current value as text (a select: its option label) and open their editor in place on focus (click, Tab, Enter / arrows from a neighbour), text selected; same padding and alignment as the text, no shift; a select's chevron shows only on hover / focus (`appearance: none` + icon). Esc restores the value and leaves the editor, the cell stays focused (typing a character, Enter or F2 reopen it; a pasted block fills from it). Enter, arrows, Tab, paste, Ctrl/Cmd+Z and `pendingChanges` unchanged; a value stored by Enter is no longer stored a second time by the blur that follows (one undo step). `TableColumn.edit` columns now call `render` (was: replaced by the editor). **Selection bar:** checked rows of an `editable` table (or with `selectionActions`) show "N selected · field (framework `Select`) · value · Apply to selected · app actions · ✕" in a bottom `ActionBar` (portalled, fixed, `--action-bar-height` reserved), no longer a row inserted above the table; Apply is a labelled button (was an empty compact square); the native `<select>`s are gone from the bar. **Empty:** one full-width row (`emptyState`, default "No data") when there is no row to show, not while loading. **Phones (< 768px, `BREAKPOINT_THRESHOLDS.tablet`):** the same markup stacks by CSS only (no JS, no second rendering): each row a block, the `sticky` column on top as its title, then "label  value" lines (`data-label` from string column titles), the open link / checkbox in the top end corner (`data-utilities` on the table), the header visually hidden, `hideOnPhone` columns left out. New `DataTableProps`: `toolbarStart`, `toolbarEnd` (one toolbar row with search and Export: `[search][toolbarStart] … [Export][toolbarEnd]`; Export is labelled from tablet up), `selectionActions(rows)`, `actionBarContent` (more content of the bottom bar, e.g. unsaved edits), `emptyState`. New `TableColumn` fields: `minWidth`, `sticky`, `lines` (`1 | 2`), `hideOnPhone`. `DataTableEditLabels.clear` (default 'Clear selection'). `TableCell` / `TableHead` take td / th attributes (`colSpan`). Migration: none required; pages with their own bottom bar (a sticky record footer) are covered by the selection bar while rows are checked.
- DataTable editable cells, accessibility: the focusable text shown before the editor has the editor's role and accessible name (`role="textbox"`, a select `role="combobox"` + `aria-expanded="false"`; `aria-label` = the column title, the `label` its editor already used). It was an anonymous `div` focus stop (`tabIndex 0`, no role, no name): keyboard and screen-reader users did not hear which column they reached. Focus still opens the editor (same role and name). `aria-invalid` / `aria-describedby` unchanged.
- DataTable number cells (`edit: { type: 'number' }`) without `render` show their value in the UI language (`Intl.NumberFormat(language)`, the language source of the table sort, from `ComponentLocaleProvider`): `29,9` and `1 234,5` in French (was the raw `29.9`). The editor still opens on the stored text (`29.9`); typing, pasting and `pendingChanges` unchanged.
- Pagination: rows-per-page choices are 25 (default, was 12), 50, 100 (`TABLE_PAGE_SIZES`; the default is `DEFAULT_TABLE_PAGE_SIZE`, the one constant DataTable, crud's stored page size and the `@donotdev/expo` DataTable read) (below the total) and "all" (were 12 / 36 / 120); the current page size is always offered (a size stored before, e.g. 12, still shows).
- Section: `titleVariant` (`'label'` default: the small uppercase accent label; `'heading'`: a plain heading, normal case, no letter spacing, the label's accent colour, for admin pages) and `titleMeta` (muted text beside the title in the title row, outside the heading, e.g. a count). Absent: markup unchanged.
- `DatePicker` / `DateTimePicker`: segment placeholders and accessible names come from `locale` (`getSegmentLabels(locale)`, `Intl.DisplayNames`): "DD/MM/YYYY" and "Day" in English, "JJ/MM/AAAA" and "Jour" in French. They were hard-coded French ("MM/JJ/AAAA", "Jour", "Heure") in every language. `DATE_SEGMENT_BASE` no longer carries `placeholder` / `ariaLabel`.
- Default theme: neutral light (zinc surfaces, `--foreground` `#09090b`, one blue primary `#1d4ed8` with white text, zinc `--secondary` `#52525b` and `--accent` `#27272a`, amber-700 `--warning` `#b45309` with white text; every `-foreground` on its colour and every colour as text on the page and on cards holds WCAG AA 4.5:1, filled-button hover included). Was Material cyan `#00bcd4` primary with black text and orange `#ff9800` accent. Buttons are rounded like cards: `--radius-interactive: var(--radius-md)` (was `0`, square). New dark theme in `styles/themes.css`: `.dark` on `<html>` (the theme store's `applyTheme` class), `color-scheme: dark`, zinc-950 page, zinc-900 cards and popovers, blue-400 primary, light fills with dark text, same AA checks; class-only selector, so an app's own `.dark` / `:root.dark` block (loaded after the framework CSS) wins token by token. Apps that set these tokens in their themes keep their colours; an app that keeps the defaults changes look, and one that does not set `--radius-interactive` gets rounded buttons. The theme switcher lists the dark theme in apps whose CSS declares no theme (`@donotdev/core` theme discovery).
- DataTable sorts natively, with no config: every column with `dataIndex` or `render` is sortable (was opt-in `sortable: true` per column; `sortable: false` on a column or `sortable={false}` on the table opt out, unchanged). A column sorts on what its cells show, in the UI language (`ComponentLocaleProvider`): numbers, booleans, `Date` and ISO date text by value (numeric / chronological, whatever `render` formats them as); other cells by the text `render` returns, read from the element tree without mounting (a reference id sorts on its label, an enum code on its translated label); the raw value when `render` shows no text. Texts compare with `Intl.Collator(language, { numeric: true, sensitivity: 'base' })`: case and accents ignored, `Lot 2` before `Lot 10` (was `<` / `>` on the raw value: uppercase before lowercase, `É` after `z`, ids instead of labels). Empty cells (`null`, `undefined`, blank, `NaN`) last in both directions; equal cells keep their order. The value is read from `row[dataIndex]` (a literal dotted key such as `'offer.price'` first, then the dot path; was `row[key]`). A shown text that is one number formatted in the UI language (separators from `Intl.NumberFormat(lang).formatToParts`, any space as a space-like group separator: NBSP, narrow NBSP), with an optional sign, currency, percent or unit word, sorts by value: `999 €` < `1 234,50 €`, `12 %`, `1,5 kg`, `-3`; a text with more (`Lot 2 de 3`, `Lot 2`) stays text. Columns with neither `dataIndex` nor `render` do not sort, nor a column with nothing to sort over the data: all its cells empty or the same (an action column with one button label, icon-only cells), or fewer than 2 rows: no arrow, no pointer cursor, header click inert. Derived once per data / columns change (`useMemo`), reading a column until its first different value. `onSort` and server pagination unchanged. One helper, exported for `@donotdev/expo`: `sortTableRows(rows, column, direction, lang)`, `tableSortValue(row, column, index, lang)`, `sortableTableColumns(rows, columns, tableSortable, lang)` (pure: the caller passes the UI language, no `document` / `navigator` read, same result on the server and the client), `isTableColumnSortable(column, tableSortable)`, types `TableSortColumn`, `TableSortDirection`, `TableSortValue`. Migration: none; `sortable: false` still opts a column out.
- `TableColumn.sortValue?: (row) => unknown` (DataTable, and `TableSortColumn` of `tableSort`): the row's sort value, used instead of the one derived from `dataIndex` / `render`, read with the same rules (numbers, dates, collator texts, empty last); a column with only `sortValue` sorts. Framework-internal for field-typed lists: `EntityList` (`@donotdev/ui`, `@donotdev/expo`) sets it on price columns, whose shown text (EUR formatted in fr-FR on any page, VAT label, discount clue: `12,19 € VAT Incl. -15%`) is no number in the UI language and sorted as text (`12,5 €` before `12,19 €`). Apps normally don't need it: put the shown value in the row instead.
- `Select`, `Combobox`, `Slider`: `aria-invalid` and `aria-describedby` props, set on the focusable control (Select trigger, Combobox input, each Slider thumb). Select spread unknown props on the Radix Root (no element) and Combobox took none, so a field could not mark them invalid or point them at its message.
- `FieldMessage` (`id`, `error?`, `helperText?`, `className?`) + `fieldMessageAria({ id, error?, helperText?, describedBy? })`: the one message slot under a form control, replacing the helper / error markup each framework field hand-rendered (crud ~30 fields, auth forms, ui `Form`). The error replaces the helper text in the same slot (IBM Carbon text input), so a field with helper text never moves; with neither, the slot is mounted but visually hidden (`dndev-sr-only`): no blank line or gap under every field. Error = `CircleAlert` icon + text in `--destructive` (WCAG 1.4.1, not colour alone). The slot holds a polite live region from the first render (WCAG technique ARIA19: a container present before the message is what screen readers announce; `polite` because entity forms re-validate while typing). `fieldMessageAria` gives the control `aria-invalid` while in error and `aria-describedby` to the slot while it shows something (plus `describedBy`). Logical properties and theme tokens only (`Label.css`). Exports `FieldMessageProps`, `FieldMessageAria`, `FieldMessageAriaOptions`, `FieldMessageState`, `fieldMessageState`.
- `PageTitle` (`title`, `meta?`, `contentWidth?`): the page's title block. The page's one `<h1>` at the theme h1 size on the start edge, an optional line under it (a string is a muted line, a node is rendered as is), in its own `Section` placed first in the `PageContainer`. Apps had no h1 to use: `Section` `title` is a small accent label (h2-h6) and `HeroSection` `title` is a styled div. Composition of Section, Stack and Text, no CSS of its own. Exports `PageTitleProps`.
- ImageGallery and Carousel translate their built-in accessible labels (region, thumbnails, previous / next, play / pause, slide, go to slide, empty and loading texts, image alt) themselves. They were hard-coded English defaults every app had to override, so a French page was announced in English. The new `ComponentLocaleProvider` (see the component locale entry) gives them the `dndev` namespace translation; keys `dndev:gallery.*` and `dndev:carousel.*` in 13 languages. The label props (`label`, `thumbnailsLabel`, `previousLabel`, `nextLabel`, `viewImageLabel`, `altPrefix`; Carousel `aria-label`, `previousLabel`, `nextLabel`, `playLabel`, `pauseLabel`, `slideLabel`, `goToSlideLabel`, `emptyLabel`, `loadingLabel`) stay optional overrides. Outside the providers the default is the key itself (fail loud).
- Menus (DropdownMenu, HeaderMenu panel): a `display="compact"` control (e.g. `LanguageSelector`) inside `.dndev-menu-content` no longer gets the icon-only geometry (48px square, zero padding and gap) while its label is forced visible; the compact resets in `patterns.css` now skip menu panels, so it takes the same AUTO width, `padding-inline` and `gap` (`--gap-sm`) as the other rows. Outside menus, compact is unchanged.
- `--section-gutter` theme token: the Section content gutter (`--gap-md`, `--gap-lg` from 1024px), declared on `:root` and nested `[data-density]`. Section, CallToAction and HeroSection pad their content with it and Floating aligns on it (same values as before; each repeated the 1024px rule); an app element that must line up with the page content (a custom header's logo) reads `var(--section-gutter)` instead of repeating the 1024px breakpoint.
- Card `coverRenditions` and ResponsiveImg `renditions` (`ImageRenditions`: `{ thumbWidth, fullWidth, sizes }`; `thumbWidth` / `fullWidth` = the frame widths of the image field's upload config, `sizes` = the `<img sizes>` value): one `<img>` with `srcset="thumb {thumbWidth}w, full {fullWidth}w"` so the browser picks the rendition by displayed size x pixel ratio instead of by viewport (a 58px tile no longer decodes the 2400px file on desktop). Applies to the cover and `coverHover`. Widths are declared from config, not measured: an image uploaded under another config gets a slightly off pick, never a broken one. Absent: unchanged `<picture>` output. Exports `ImageRenditions`.
- Section: `actions` (`ReactNode`) puts controls at the end of the title row, beside the heading ("See all", "Add to cart"). Wrapped in a flex row only when set (absent: markup and CSS unchanged); wraps under the heading, start-aligned, on a narrow row; with `collapsible` the actions are a sibling of the heading, never inside the trigger button (no nested interactive, clicking one does not toggle). Logical properties, no layout shift.
- Accordion: `gridCols` (same type and breakpoints as `Section`'s `gridCols`) lays the items in a responsive grid, cells aligned to the start; e.g. a FAQ in `[1, 1, 2, 2]`. Reuses Grid's column mapping through the new `getGridColsProps` helper (Grid output unchanged). Absent: unchanged single column.
- QuantityStepper: the typed-quantity `<input>` uses `--font-size-input` (16px floor) instead of inheriting the surrounding font, so iOS Safari no longer zooms on focus when the body text is under 16px. Box size unchanged (cells are fixed).
- List: `marker="none"` (`ListMarker`) hides every drawn marker (counter numbers, bullets) and keeps the `<ol>`/`<ul>`, spacing and alignment; sets `role="list"` (Safari/VoiceOver drops list semantics when markers are hidden, webkit.org/b/170179) and `data-marker="none"`. For steps already numbered by a caption. Absent: unchanged.
- Text: `underline` (non-link text that must read as a link cue) and `lines` (clamp to N lines with an ellipsis; `data-lines` + `--text-lines`, invalid values ignored). Apps needed inline `style` for both (shopkb product card).
- QuantityStepper: `addLabel` (with `collapseWhenZero`, horizontal only; ignored with `vertical`) shows the collapsed control as one "+ label" button over the expanded footprint (`fullWidth`: the full width) instead of the square +, which read as a disclosure toggle (shopkb cards: "Ajouter"). The first + crossfades it into [ − qty + ] (opacity only, no size change: no layout shift); `incrementLabel` stays the accessible name; keyboard, focus and press-and-hold unchanged (a hold started on the label keeps the pointer captured while the + returns to its cell).
- Button `badge`: the count bubble pops (scale, Web Animations API) when its numeric value increases after mount, 0 → 1 included; never on the first render / hydration, a decrease, a text badge, or under `prefers-reduced-motion: reduce`. Add-to-cart feedback without a toast. While a `flyTo` flight heads to the button, an increase waits: the previous count stays shown until the image lands, then the latest count shows and pops (cancelled flight: shown, no pop). The bubble is a small client island; the rest of Button stays server-renderable.
- QuantityStepper: `flyFrom` (ref), `flyTo` (`flyTarget()` name or element) and `flyEveryAdd` (default `false`: first add only) fly an image to the cart on a committed add (click, hold release, typed / keyed higher value: a hold flies once, on release), started before `onChange`, so the header badge pops when the image lands. Editable (`onChange`) mode only. `onChange` may return the write's promise (`void | Promise<unknown>`): a rejection cancels the flight. Non-breaking.
- `flyTo(source, target, { duration })` / `flyTarget(name)`: fly-to-cart primitive. `flyTarget(name)` is a stable callback ref registering a target (several per name allowed: the first on screen wins); `flyTo` flies a fixed-position clone of `source` (an `<img>` flies its displayed `currentSrc`) onto the target with the Web Animations API (transform / opacity only), removes it on finish / cancel, and is a no-op under reduced motion, when the source is missing, detached or unrendered, or when the target is missing, detached or off-screen. A source scrolled off screen flies from its box clamped just beyond the nearest viewport edge. A Button `badge` inside the target holds its update until the landing. Exports `flyTo`, `flyTarget`, `FlyToOptions`.
- Card `coverRef`, ImageGallery `imageRef` (the image in view; follows the current slide) and ResponsiveImg `ref`: refs to the displayed `<img>`, e.g. as a `flyTo` source.
- Removed `PortalButton` (and `PortalButtonProps`): use `Floating` + `Button`.
- Button: removed the `floating` prop (it only set `data-floating`, which no CSS read). Position a control with `Floating`.

- Floating: new component, a container for one small control that stays on screen while the page scrolls (shopkb PDP "Back to catalogue"). Props: `children`, `placement` (`FloatingPlacement`: `'top-start' | 'top-end' | 'bottom-start' | 'bottom-end'`, default `'top-start'`). Top placements: rendered in place (server HTML, no hydration shift), `position: sticky`, first in the page: `--gap-md` above and below at rest, sticks `--gap-md` below the top of the layout `<main>`; inline at the Section content edge (`--gap-md`, `--gap-lg` from 1024px), as wide as the control. Section: a ghost Section right after a top Floating drops its top padding, so the control sits `--gap-md` from the header and from the Section's first line at every width. Bottom placements: fixed, portalled to `<body>`, render nothing on the server; `--gap-md` above `--action-bar-height` (shown ActionBar) or the bottom safe area; inline: Section gutter after `--sidebar-width` on the start side, outside side safe areas. Logical properties, `--z-header`. Exports `Floating`, `FloatingProps`, `FloatingPlacement`.
- Text: `as="s"` renders the native `<s>` element, struck through (`text-decoration-line: line-through`, re-asserted like `strong` / `em`): a former price beside the new one. Apps needed an inline `style` for it (shopkb PDP).
- ActionBar: new component (BUGS #23), a page action bar fixed to the bottom of the viewport (sticky buy bar). Props: `children`, `hideFrom` (`ActionBarBreakpoint`: `'tablet' | 'laptop' | 'desktop'`, hidden from that width up), `revealAfter` (ref; shown only while that element has scrolled up out of view). Portalled to `<body>`, `--z-header`, safe-area padded (with `viewport-fit=cover`); while shown it sets its measured height as `--action-bar-height` on `<html>` and DnDevLayout (`@donotdev/ui`) reserves it at its bottom, so the last content and the footer scroll above the bar (BUGS #36: it covered them); nothing reserved while hidden or at load (no layout shift); hidden = `inert` + `visibility: hidden`; reduced-motion aware; renders nothing on the server. Exports `ActionBar`, `ActionBarProps`, `ActionBarBreakpoint`.
- NavigationMenu: item field `active` (`NavigationMenuItem`) marks the current page: its link gets `aria-current="page"` and `data-active="true"`, with an accent background. Sub-menu lists no longer show bullets (`base.css` gives every `ul` `list-style: disc` and only the top-level list reset it).
- `--floating-background` theme token: a theme sets it (e.g. `var(--popover)`) to flatten every floating surface (Popover, DropdownMenu, NavigationMenu, ...). Unset keeps the glow gradient. `.dndev-floating` always painted the gradient; only `data-glow=blank` components (Select, Combobox, Code) could go flat. Documented in core `THEMES.md`.
- Calendar loads on demand outside DatePicker too: new exports `LazyCalendar` (`errorLabel` required, shown if the chunk cannot load), `preloadCalendar` (call on trigger pointer-enter / focus) and `useIdlePreloadCalendar()` (preload when the browser is idle), plus the type `LazyCalendarProps`.

### Patch Changes

- Combobox options: the option under the pointer / keyboard (`.dndev-combobox-option-highlighted`) took the `--accent` fill with its texts left on `--foreground` (label, description, count) and the check on `--primary`: unreadable wherever `--accent` is dark or close to the text colour (the default theme: zinc-800 fill, zinc-950 text). Its texts and check now take `--accent-foreground`, the fill's pair, as every other filled state in the package. The row is no longer faded (`opacity: var(--opacity-strong)` removed). A selected option not under the pointer has a 10% `--accent` tint (was 50%, a mid-tone that left the check below 3:1), its check and medium weight, texts on the surface's foreground; selected and under the pointer: the fill, check in `--accent-foreground`. Migration: none.

- Focus ring is solid (`--shadow-focus: 0 0 0 3px var(--ring)`, owner decision 2026-11-27 W1, `docs/decisions/2026-11-27-accordion-a11y-perf-dead-classes.html`). It was `--ring` mixed 50% with transparent: 2.37:1 against the page with the default blue on white, 1.66:1 with a gold `--ring` on an off-white page; WCAG 2.4.13 (AAA) needs a 3:1 change. Every interactive control's focus ring is stronger in every app; an app whose `--ring` is light on its background (3:1 or less) should darken it.
- Accordion trigger keeps the 48px `--touch-target` minimum height of every `.dndev-interactive` (owner decision 2026-11-27 W2, `docs/decisions/2026-11-27-accordion-a11y-perf-dead-classes.html`): `Accordion.css` overrode it with `min-height: auto`, so a one-line question was about 35px tall on a 375px phone (padding `--gap-md` = `min(1rem, 2vw)`), under WCAG 2.5.5 (AAA, 44px). FAQ rows are taller on phones.
- Marquee `pauseOnHover` / `pauseOnFocusWithin` each work on their own (owner decision 2026-11-27 T2, `docs/decisions/2026-11-27-accordion-a11y-perf-dead-classes.html`). They set the classes `group` and `focus-within:group`, and `Marquee.css` paused on `.group:hover` and `.group:focus-within`: `pauseOnHover` also paused on focus, `pauseOnFocusWithin` alone never paused. Now `data-marquee-pause-hover` / `data-marquee-pause-focus` on the strip, read by `Marquee.css`; JSDoc on both props.
- Label: `.dndev-label-base[data-state='error']` is `--destructive` (the same hook as `.dndev-field-message`), set by the `@donotdev/ui` `FormLabel` on a field in error.
- Dead Tailwind classes removed, no visual change (owner decision 2026-11-27 T3, `docs/decisions/2026-11-27-accordion-a11y-perf-dead-classes.html`): Tooltip content (`animate-in`, `fade-*`, `zoom-*`, `slide-in-from-*`: no CSS defined them, tooltips do not animate), Checkbox root (`peer`). JSDoc examples of ContextMenu, Popover and Separator use framework components instead of Tailwind classes.
- Accordion opens and closes with a height and opacity animation again (owner decision 2026-11-27 A1, `docs/decisions/2026-11-27-accordion-ripple-motion.html`). Since 0.3.5 the page jumped to full height on open (fade only) and closing was instant (`display: none`). Content now has a collapse layer, `.dndev-accordion-content-grid` > `.dndev-accordion-content-clip` > `.dndev-accordion-content-inner`: one grid row animates `1fr` / `0fr` (`--dur-normal`, `--ease-in-out`, no measured height), closed = `visibility: hidden` once collapsed (not visible, focusable or announced; was `display: none`). Closed content stays in the server HTML (`forceMount`). The transition is on the layer, not on Content, because Radix sets an inline `transition-duration: 0s` on Content while it measures.
