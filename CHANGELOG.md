# @donotdev/components

## Unreleased

### Minor Changes

- `Select`, `Combobox`, `Slider`: `aria-invalid` and `aria-describedby` props, set on the focusable control (Select trigger, Combobox input, each Slider thumb). Select spread unknown props on the Radix Root (no element) and Combobox took none, so a field could not mark them invalid or point them at its message.
- `FieldMessage` (`id`, `error?`, `helperText?`, `className?`) + `fieldMessageAria({ id, error?, helperText?, describedBy? })`: the one message slot under a form control, replacing the helper / error markup each framework field hand-rendered (crud ~30 fields, auth forms, ui `Form`). The error replaces the helper text in the same slot (IBM Carbon text input), so a field with helper text never moves; with neither, the slot is mounted but visually hidden (`dndev-sr-only`): no blank line or gap under every field. Error = `CircleAlert` icon + text in `--destructive` (WCAG 1.4.1, not colour alone). The slot holds a polite live region from the first render (WCAG technique ARIA19: a container present before the message is what screen readers announce; `polite` because entity forms re-validate while typing). `fieldMessageAria` gives the control `aria-invalid` while in error and `aria-describedby` to the slot while it shows something (plus `describedBy`). Logical properties and theme tokens only (`Label.css`). Exports `FieldMessageProps`, `FieldMessageAria`, `FieldMessageAriaOptions`, `FieldMessageState`, `fieldMessageState`.
- `PageTitle` (`title`, `meta?`, `contentWidth?`): the page's title block. The page's one `<h1>` at the theme h1 size on the start edge, an optional line under it (a string is a muted line, a node is rendered as is), in its own `Section` placed first in the `PageContainer`. Apps had no h1 to use: `Section` `title` is a small accent label (h2-h6) and `HeroSection` `title` is a styled div. Composition of Section, Stack and Text, no CSS of its own. Exports `PageTitleProps`.
- ImageGallery and Carousel translate their built-in accessible labels (region, thumbnails, previous / next, play / pause, slide, go to slide, empty and loading texts, image alt) themselves. They were hard-coded English defaults every app had to override, so a French page was announced in English. A new `TranslatorProvider` / `useComponentTranslate` (`ComponentTranslate`; same layering as `LinkRendererProvider`, this package cannot import `@donotdev/core`) is mounted by `@donotdev/ui` `UIProviders` with the `dndev` namespace translation; keys `dndev:gallery.*` and `dndev:carousel.*` in 13 languages. The label props (`label`, `thumbnailsLabel`, `previousLabel`, `nextLabel`, `viewImageLabel`, `altPrefix`; Carousel `aria-label`, `previousLabel`, `nextLabel`, `playLabel`, `pauseLabel`, `slideLabel`, `goToSlideLabel`, `emptyLabel`, `loadingLabel`) stay optional overrides. Outside the providers the default is the key itself (fail loud).
- Menus (DropdownMenu, HeaderMenu panel): a `display="compact"` control (e.g. `LanguageSelector`) inside `.dndev-menu-content` no longer gets the icon-only geometry (48px square, zero padding and gap) while its label is forced visible; the compact resets in `patterns.css` now skip menu panels, so it takes the same AUTO width, `padding-inline` and `gap` (`--gap-sm`) as the other rows. Outside menus, compact is unchanged.
- `--section-gutter` theme token: the Section content gutter (`--gap-md`, `--gap-lg` from 1024px), declared on `:root` and nested `[data-density]`. Section, CallToAction and HeroSection pad their content with it and Floating aligns on it (same values as before; each repeated the 1024px rule); an app element that must line up with the page content (a custom header's logo) reads `var(--section-gutter)` instead of repeating the 1024px breakpoint.
- Card `coverRenditions` and ResponsiveImg `renditions` (`ImageRenditions`: `{ thumbWidth, fullWidth, sizes }`; `thumbWidth` / `fullWidth` = the frame widths of the image field's upload config, `sizes` = the `<img sizes>` value): one `<img>` with `srcset="thumb {thumbWidth}w, full {fullWidth}w"` so the browser picks the rendition by displayed size x pixel ratio instead of by viewport (a 58px tile no longer decodes the 2400px file on desktop). Applies to the cover and `coverHover`. Widths are declared from config, not measured: an image uploaded under another config gets a slightly off pick, never a broken one. Absent: unchanged `<picture>` output. Exports `ImageRenditions`.
- Section: `actions` (`ReactNode`) puts controls at the end of the title row, beside the heading ("See all", "Add to cart"). Wrapped in a flex row only when set (absent: markup and CSS unchanged); wraps under the heading, start-aligned, on a narrow row; with `collapsible` the actions are a sibling of the heading, never inside the trigger button (no nested interactive, clicking one does not toggle). Logical properties, no layout shift.
- Accordion: `gridCols` (same type and breakpoints as `Section`'s `gridCols`) lays the items in a responsive grid, cells aligned to the start; e.g. a FAQ in `[1, 1, 2, 2]`. Reuses Grid's column mapping through the new `getGridColsProps` helper (Grid output unchanged). Absent: unchanged single column.
- QuantityStepper: the typed-quantity `<input>` uses `--font-size-input` (16px floor) instead of inheriting the surrounding font, so iOS Safari no longer zooms on focus when the body text is under 16px. Box size unchanged (cells are fixed).
- List: `marker="none"` (`ListMarker`) hides every drawn marker (counter numbers, bullets) and keeps the `<ol>`/`<ul>`, spacing and alignment; sets `role="list"` (Safari/VoiceOver drops list semantics when markers are hidden, webkit.org/b/170179) and `data-marker="none"`. For steps already numbered by a caption. Absent: unchanged.
- Text: `underline` (non-link text that must read as a link cue) and `lines` (clamp to N lines with an ellipsis; `data-lines` + `--text-lines`, invalid values ignored). Apps needed inline `style` for both (shopkb product card).
- QuantityStepper: `addLabel` (with `collapseWhenZero`, horizontal only; ignored with `vertical`) shows the collapsed control as one "+ label" button over the expanded footprint (`fullWidth`: the full width) instead of the square +, which read as a disclosure toggle (shopkb cards: "Ajouter"). The first + crossfades it into [ − qty + ] (opacity only, no size change: no layout shift); `incrementLabel` stays the accessible name; keyboard, focus and press-and-hold unchanged (a hold started on the label keeps the pointer captured while the + returns to its cell).
- Button `badge`: the count bubble pops (scale, Web Animations API) when its numeric value increases after mount, 0 → 1 included; never on the first render / hydration, a decrease, a text badge, or under `prefers-reduced-motion: reduce`. Add-to-cart feedback without a toast. While a `flyTo` flight heads to the button, an increase waits: the previous count stays shown until the image lands, then the latest count shows and pops (cancelled flight: shown, no pop). The bubble is a small client island; the rest of Button stays server-renderable.
- QuantityStepper: `flyFrom` (ref), `flyTo` (`flyTarget()` name or element) and `flyEveryAdd` (default `false`: first add only) fly an image to the cart on a committed add (click, hold release, typed / keyed higher value: a hold flies once, on release), started before `onChange`, so the header badge pops when the image lands. Editable (`onChange`) mode only. `onChange` may return the write's promise (`void | Promise<unknown>`): a rejection cancels the flight. Non-breaking.
- `flyTo(source, target, { duration })` / `flyTarget(name)`: fly-to-cart primitive. `flyTarget(name)` is a stable callback ref registering a target (several per name allowed: the first on screen wins); `flyTo` flies a fixed-position clone of `source` (an `<img>` flies its displayed `currentSrc`) onto the target with the Web Animations API (transform / opacity only), removes it on finish / cancel, and is a no-op under reduced motion, when the source is missing, detached or unrendered, or when the target is missing, detached or off-screen. A source scrolled off screen flies from its box clamped just beyond the nearest viewport edge. A Button `badge` inside the target holds its update until the landing. Exports `flyTo`, `flyTarget`, `FlyToOptions`.
- Card `coverRef`, ImageGallery `imageRef` (the image in view; follows the current slide) and ResponsiveImg `ref`: refs to the displayed `<img>`, e.g. as a `flyTo` source.
- Removed `PortalButton` (and `PortalButtonProps`): use `Floating` + `Button`.
- Button: removed the `floating` prop (it only set `data-floating`, which no CSS read). Position a control with `Floating`.

- Floating: new component, a container for one small control that stays on screen while the page scrolls (shopkb PDP "Back to catalogue"). Props: `children`, `placement` (`FloatingPlacement`: `'top-start' | 'top-end' | 'bottom-start' | 'bottom-end'`, default `'top-start'`). Top placements: rendered in place (server HTML, no hydration shift), `position: sticky`, first in the page: `--gap-md` above and below at rest, sticks `--gap-md` below the top of the layout `<main>`; inline at the Section content edge (`--gap-md`, `--gap-lg` from 1024px), as wide as the control. Section: a ghost Section right after a top Floating drops its top padding, so the control sits `--gap-md` from the header and from the Section's first line at every width. Bottom placements: fixed, portalled to `<body>`, render nothing on the server; `--gap-md` above `--action-bar-height` (shown ActionBar) or the bottom safe area; inline: Section gutter after `--sidebar-width` on the start side, outside side safe areas. Logical properties, `--z-header`. Exports `Floating`, `FloatingProps`, `FloatingPlacement`.
- Text: `as="s"` renders the native `<s>` element, struck through (`text-decoration-line: line-through`, re-asserted like `strong` / `em`): a former price beside the new one. Apps needed an inline `style` for it (shopkb PDP).
- ActionBar: new component (BUGS #23), a page action bar fixed to the bottom of the viewport (sticky buy bar). Props: `children`, `hideFrom` (`ActionBarBreakpoint`: `'tablet' | 'laptop' | 'desktop'`, hidden from that width up), `revealAfter` (ref; shown only while that element has scrolled up out of view). Portalled to `<body>`, `--z-header`, safe-area padded (with `viewport-fit=cover`); while shown it sets its measured height as `--action-bar-height` on `<html>` and DnDevLayout (`@donotdev/ui`) reserves it at its bottom, so the last content and the footer scroll above the bar (BUGS #36: it covered them); nothing reserved while hidden or at load (no layout shift); hidden = `inert` + `visibility: hidden`; reduced-motion aware; renders nothing on the server. Exports `ActionBar`, `ActionBarProps`, `ActionBarBreakpoint`.
- NavigationMenu: item field `active` (`NavigationMenuItem`) marks the current page: its link gets `aria-current="page"` and `data-active="true"`, with an accent background. Sub-menu lists no longer show bullets (`base.css` gives every `ul` `list-style: disc` and only the top-level list reset it).
- `--floating-background` theme token: a theme sets it (e.g. `var(--popover)`) to flatten every floating surface (Popover, DropdownMenu, NavigationMenu, ...). Unset keeps the glow gradient. `.dndev-floating` always painted the gradient; only `data-glow=blank` components (Select, Combobox, Code) could go flat. Documented in core `THEMES.md`.
- Calendar loads on demand outside DatePicker too: new exports `LazyCalendar` (`errorLabel` required, shown if the chunk cannot load), `preloadCalendar` (call on trigger pointer-enter / focus) and `useIdlePreloadCalendar()` (preload when the browser is idle), plus the type `LazyCalendarProps`.

### Patch Changes

- Progress: indeterminate when `value` is absent (`null` / `undefined`). Radix sets `data-state="indeterminate"` and no `aria-valuenow` (assistive tech reads busy); the indicator is a 40% segment travelling along the inline axis (`inset-inline-start` keyframes: mirrored in RTL), a still full bar under `prefers-reduced-motion`. The primitive no longer forces `aria-valuenow={value ?? 0}` and `aria-valuemin` / `aria-valuemax` (Radix sets them from `value` / `max`): a bar without a value was announced as 0%.
- Floating-label fields (`.dndev-floating-fieldset`, every crud field): an invalid control inside (`aria-invalid="true"`) turns the fieldset border and the legend `--destructive`, at rest, on hover and while focused (`:has()`). The red rule of `Input.css` targets the control, whose own border is transparent inside the fieldset: an invalid field showed its message but kept the neutral border. CSS only.
- Sheet opens in `--dur-slow` (500ms) instead of `--dur-heavy` (700ms), same `--ease-heavy`; closing stays `--dur-normal` (300ms). 700ms is Material 3's first "extra long" step (androidx `MotionTokens`: long 450-600, extra long 700-1000); shadcn's Sheet opens in 500ms and closes in 300ms. Every cart drawer / auth panel open waited 0.7s. The duration tokens are unchanged. CSS only.
- Floating: the control (the container's child) always carries the theme's medium shadow, `--shadow-md` (`--shadow-md-rtl` under `:dir(rtl)`, as `[data-shadow='md']`), at every placement. A sticky top control (the shop's "Retour au catalogue") read as part of the content it covered while scrolling. `md` is the smallest level that shows on the page background (`sm` is a 2px hairline, `xl` a 24px blur). CSS only.
- Section, CallToAction, HeroSection `bleed`: the band is `100cqi` wide (`margin-inline: calc(50% - 50cqi)`), not `100vw`. `cqi` resolves against the layout's `<main>` (an inline-size container in `@donotdev/ui`): its content box, without the scrollbar. `100vw` includes a classic scrollbar (10px on desktop Chrome / Firefox for Windows and Linux): the band overflowed main by half of it (a horizontal scroll of 5px) and sat 5px off the page content. Without the UI layout (no container) `cqi` resolves against the viewport, as before.
- Card: the root is a flex column (was a grid with `align-content: start`) and the body fills its remaining height with the footer at its bottom (`margin-block-start: auto`): in a row of equal-height cards the footers (CTAs) line up. The root no longer sets an inline `height: 100%`: a stretched grid / flex item (Grid's default `align="stretch"`) still fills its row, and a parent aligned to the start (`align="start"`) now keeps the card at its content height (the shop's cart recap stretched to the lines column). A Card inside a plain block wrapper no longer fills that wrapper: give the wrapper the layout, or put the Card directly in the Grid / Stack.
- Section: the content container is a flex column with `gap: --gap-md` (was `display: block`): children are spaced, and `align` / `justify` (align-items / justify-content, as documented) take effect. The title (or title row with `actions`) drops its own bottom margin there (the gap spaces it); collapsible sections keep it.
- DescriptionList `orientation="horizontal"`: rows spaced by `--gap-sm` (was `--gap-lg`, looser than the two-line vertical items: summary rows ~68px apart).
- Card `coverBackground` docs: it fills the cover region whatever the cover, image or ReactNode (e.g. an empty placeholder keeping the image slot); it said "string / image covers only", the behaviour was already this.
- Floating surfaces (`.dndev-floating`: Popover, DropdownMenu, Select, ContextMenu, Combobox, DatePicker, NavigationMenu viewport) open and close with one motion, the dialog's (`floating-in` / `floating-out`: fade + scale 0.96, `--dur-normal`, `--ease-in-out`, from the Radix popper transform origin). They had none: the HeaderMenu burger popover snapped open while Dialog and Sheet animated. Animates `scale`, so the surface's own `transform` stays; `prefers-reduced-motion` already cancels it (base.css).
- Button `link` variant: a text link. `display: inline-flex` + `width: fit-content` (as wide as its label: in a start-aligned column it was stretched to the column's width with the label centred in it, e.g. a cart line's product name), `font-size: inherit` (its text's size), `min-height: var(--target-min)`, the new 24px token (WCAG 2.2 SC 2.5.8 minimum target; it was `auto`, 21px). One rule for every text link: the footer legal and branding links (`@donotdev/ui`) now render with it.
- Sheet header: inline padding `--gap-md` on both sides, the body's inset (was start only, the close button `margin-inline-end: --gap-sm`): the title starts and the close button ends on the content's edges instead of the X overhanging the content by the difference.

- Current-page tint (`--accent` at 50%, `NavigationMenu.css`) also applies to a `Button` carrying `data-active="true"` (the `HeaderNavigation path` link), hover included.

- Button `loading`: the button keeps its variant colours (spinner in the label colour); only the spinner shows the loading. 0.3.5 gave it the muted disabled look: the click that started loading faded the button to `--muted` over 150 ms under the click ripple, read as a flash (shopkb sign-up). Still disabled (`disabled`, `aria-busy`, `cursor: wait`); a disabled Button that is not loading keeps the muted look. CSS only.
- `.dndev-animate-step-forward` / `-back` (auth `EmailSignUpFlow` step change): `--ease-heavy` instead of `--ease-in-out`. The previous step is hidden at once and the entering one fades in from transparent; the slow start left the container blank for ~100 ms (shopkb sign-up, account → code). Same duration and slide. CSS only.
- Button / `.dndev-interactive`: a control rendered as a link (`render={(p) => <Link {...p} />}`, so an `<a class="dndev-interactive">`) has no underline. `base.css` resets `text-decoration` only for `a:not(.dndev-interactive)` and the control styles never did, so the browser underline showed on an outline / ghost Button link. `.dndev-interactive` now sets `text-decoration: none`; `variant="link"` keeps its underline. CSS only.
- Section: consecutive Sections share one gap (BUGS #38). Each page Section pads its content `--gap-lg` top and bottom, so two in a row were 2 × `--gap-lg` apart (~100-130 px at desktop), more than a one-line section's content. A `ghost` Section directly after a `ghost` Section now has no top padding. A toned Section (background band) keeps its padding on both sides, so a band edge never touches text. CSS only, no new prop, no `:has()`.
- Section: a Section nested inside another Section's content is flush (BUGS #37). It repeated the page band: own `max-width`, auto margins, side padding (`--gap-md` / `--gap-lg`) and block padding, so a collapsible "Description" in a grid column started ~48 px in from the column edge. Nested, it now takes its container's edge and width with no padding; spacing comes from the parent layout. A nested Section with a `tone` other than `ghost` keeps its padding (its background must not sit on the text edge). CSS only, no new prop.
- Text: a link inside text-level Text (`body` / `small` / `caption`, the default; `a:not(.dndev-interactive)`) is underlined (`text-decoration: underline; text-underline-offset: 2px`, as Button `variant="link"`). Not inside a heading level (`h1`-`h6`): it underlined product card titles (a `Link` in a Card title at `h3`), which are titles, not running text. `base.css` stripped the underline from every anchor, so a `Link` in running text differed from the text only by colour (WCAG 1.4.1; shopkb PDP).
- Text: a heading element at a text level (`<Text as="h2" level="body">`, also `small` / `caption`) takes the body font and drops the heading case / tracking from `base.css`. It kept the headline font, so a serif display theme rendered body-sized section labels in a narrow serif that read smaller than the body (shopkb PDP).
- ImageGallery: bounded by the viewport (BUGS #34). The main image took its height from `aspectRatio` and the column width only, so a 1:1 product gallery in a half-width column ran past the bottom of the screen (shopkb PDP: 1920x1080 gallery bottom at 1101 px, 1366x768 at 898 px). Main image + thumbnail row now fit in `100svh - --header-height - 2 × --gap-lg` (`vh` fallback): past that the gallery narrows and centres at its ratio. Thumbnails are one row that scrolls natively when it overflows (was a wrapping grid, whose row count made any height bound impossible) and follows the selection; thumbnail focus ring drawn inset (the row clips outside it). No new prop; the ratio is the `--image-gallery-ratio` custom property set from `aspectRatio`.
- Collapsible / Accordion / Section `collapsible`: closed content is in the server HTML (BUGS #20, SEO). `CollapsibleContent` and `AccordionContentPrimitive` always force-mount; `.dndev-collapsible-content[data-state='closed']` / `.dndev-accordion-content[data-state='closed']` hide it with `display: none` (not visible, focusable or announced), like Tabs inactive panels. Behaviour change: closed content mounts eagerly (its effects run while closed); opening is a fade (shared `fade-in` keyframes, no height slide: Radix cannot measure force-mounted content, the height jumped mid-animation) and collapsing is instant; `slideDown` / `slideUp` keyframes removed. `CollapsibleContent` now always sets the `dndev-collapsible-content` class.
- Section `collapsible`: the trigger is a real `<button>` inside the title heading (WAI-ARIA disclosure, like Accordion), so it is in the tab order and Enter / Space toggle it (BUGS #33; was a `div`: no role, no tab stop, no keyboard). Visual unchanged.
- List: `ordered` shows its numbers (BUGS #31). The items are flex rows (icon alignment) and a flex item gets no `::marker`, so the `<ol>` rendered without numbers; they are now drawn with a CSS counter (`1.`, tabular numerals, before the icon if any).
- List: an unordered `List` shows a bullet on items without an icon (BUGS #31, same cause as the numbers: flex items get no `::marker`). Icon-less items carry `data-plain` and draw a `•` in `::before`; items with an icon are unchanged, and so are ordered lists.
- Marquee keeps its item type: the exported component is generic (`Marquee<T>`, like `Carousel`), so `renderItem` receives the type of `items`. The lazy-loading wrapper typed its props from `React.lazy`, which erases the generic, and consumers cast `unknown`.
- Text: an explicit `level` on a heading tag (`<Text as="h2" level="body">`) always emits `data-level`, so it beats the `base.css` heading size (it emitted none and kept the h2 size). The implicit `body` default still omits it: plain `Text` DOM is unchanged.
- Slider: `aria-label` / `aria-labelledby` are applied to the thumb (the `role="slider"` element) so the slider has an accessible name; previously they landed on the root span.
- Accordion: `titleAs` (`'h2'`-`'h6'`, default `'h3'`) sets the heading level wrapping each trigger. Default unchanged.
- Combobox: `multiple` without `chips` shows the selection (one value's label, `selectedLabel` for several; was empty with the placeholder). `clearLabel` labels the clear button (default 'Clear').
- Tag: `removeLabel` labels the remove button (default 'Remove').
